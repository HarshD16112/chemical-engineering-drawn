# Source — how `Nomograph.html` is built

The live tool at **https://harshd16112.github.io/chemical-engineering-drawn/**
ships as a single self-contained file, `Nomograph.html`, at the repo root. That
one file is a *bundle* — all of React, KaTeX, the fonts and the whole
application are packed into it so it runs offline with no network calls. It is
also why GitHub refuses to preview it ("we can't show files that are this big").

This `src/` folder is the **same application, unpacked into readable pieces** so
you (and GitHub) can actually read it, module by module. Nothing here is a
rewrite: a build step reassembles these files and verifies, byte-for-byte, that
they reproduce exactly the application that is deployed.

```
 src/ (readable modules)  ──►  node tools/build.mjs  ──►  build/app.html
                                                             │
                                          Claude artifact publisher inlines
                                          React + KaTeX + fonts
                                                             ▼
                                                    Nomograph.html (deployed)
```

`build/app.html` is the authored application document. The final publish step
(Claude's artifact publisher) wraps it — inlining the libraries and fonts — into
the self-contained `Nomograph.html`. **No tool in this folder writes to
`Nomograph.html`; the deployed site is never touched by a build.**

## Layout

| Folder | What it holds |
| --- | --- |
| `document/` | The HTML skeleton — `<head>` (React loader), the KaTeX & runtime loaders, the preview markup, and the `<script>` frame the app lives in. |
| `styles/` | The CSS, split out: `design-system.css` (the look — the source of truth), `fonts-barlow.css`, `katex.css`, `app.css`. |
| `engine/` | The shared core of the `Component` class — compound/thermo data, unit conversion, the offline TeX renderer, numeric helpers, the plot/canvas/schematic drawing kit, module-state plumbing and the coverage audit. Every module is built on these. |
| `modules/` | **One file per module group** — the 135 calculators, grouped by subject. This is the part you came for. |
| `data/` | `nomenclature.js` — what every symbol in every equation means. |
| `build-manifest.json` | The order the files are concatenated in. The build reads this; don't hand-edit it (it is regenerated by `tools/split.mjs`). |

> The `engine/` and `modules/` files are **fragments of one JavaScript class**,
> assembled in order by the build — so an individual file is readable but not a
> standalone module. The numeric filename prefixes are the assembly order.

## Building

```bash
node tools/build.mjs     # reassemble src/ -> build/app.html, verify vs deployed
node tools/split.mjs     # (re)generate src/ from the current Nomograph.html
```

`build.mjs` fails loudly if the reassembled document does not match the app
embedded in `Nomograph.html`, so `src/` can never silently drift from the live
tool. If you ever publish a new `Nomograph.html`, run `node tools/split.mjs` to
refresh `src/` from it.
